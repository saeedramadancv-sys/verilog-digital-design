# الجزء الأول: الـ ALU

## شو هي ولاقفة وين

الـ ALU هي الوحدة اللي بتعمل العمليات الحسابية والمنطقية جوّا المعالج.
بتاخد رقمين (`a` و `b`) وكود عملية (`opcode`)، وبترجّع نتيجة + أعلام (flags).

**الملف:** `rtl/alu.v`

## ليش combinational بلا clock؟

الـ ALU **ما فيها أي `always @(posedge clk)`** — يعني ما فيها ذاكرة، المخرج
بيتغيّر فوراً لما يتغيّر المدخل.

**السبب:** الـ ALU بتقعد جوّا الـ datapath وبين registers. لازم تخلّص شغلها
خلال **دورة clock وحدة**. لو حطينا register جوّاها، بنكون فرضنا قرار الـ
pipelining على مستوى غلط — هاد قرار بيتاخد فوق، مش جوّا الـ ALU.

> **سؤال متوقع:** "ليش ما حطيت register على المخرج؟"
> **جوابك:** لأن هاد بيغيّر عقد الوحدة. الـ ALU وحدة combinational بتعريفها،
> والـ pipelining قرار معماري بيتاخد بمستوى الـ datapath.

## القرار الأهم: adder واحد مش اتنين

```verilog
wire             is_sub   = (opcode == OP_SUB) || (opcode == OP_SLT);
wire [WIDTH-1:0] add_b    = is_sub ? ~b : b;
wire             carry_in = is_sub ? 1'b1 : 1'b0;
wire [WIDTH:0]   sum      = {1'b0, a} + {1'b0, add_b} + carry_in;
```

**الفكرة:** بالمتمّم الثنائي (two's complement)، الطرح هو جمع:

```
a - b  =  a + (-b)  =  a + (~b) + 1
```

فبدل ما نكتب `a + b` و `a - b` ونخلّي المترجم يبني **دارتين جمع**، بنقلب `b`
(`~b`) وبنزيد 1 عن طريق `carry_in`، وبنستعمل **نفس الـ adder**.

**ليش هاد مهم:** على FPGA، الـ adder بياخد carry chain — وهي مورد محدود.
adder واحد بدل اتنين بيوفّر نص المساحة لهالجزء.

> **سؤال متوقع:** "ليش `sum` عرضها `WIDTH:0` مش `WIDTH-1:0`؟"
> **جوابك:** عشان الـ carry-out يطلع طبيعي بالبت الزايد فوق. لو خليتها بنفس
> العرض، بضطر أحسب الـ carry من إشارات المدخلات يدوي — وهاد مصدر أخطاء.

## الفرق بين Carry و Overflow — وهاد بينسألوا عنه كتير

هدول **مش نفس الإشي** وكتير ناس بتخلط بينهم.

| | يعني | بتهمّ لما |
|---|---|---|
| **Carry** | خرج بت من فوق الـ adder | تعامل الأرقام كـ **unsigned** |
| **Overflow** | النتيجة طلعت برّا المدى المسموح | تعامل الأرقام كـ **signed** |

### مثالين بيثبتوا إنهم مستقلين

**١. Overflow بلا Carry:**
```
100 + 50 = 150
```
بـ 8 بت signed، المدى من -128 لـ 127. النتيجة 150 برّا المدى، فبتنقرأ **-106**.
الإشارة انقلبت ← **overflow = 1**
بس ما خرج ولا بت من فوق ← **carry = 0**

**٢. Carry بلا Overflow:**
```
-1 + 1 = 0     (أي 255 + 1 بـ unsigned)
```
النتيجة 256، ما بتسع بـ 8 بت ← **carry = 1**
بس signed، -1 + 1 = 0 صح تماماً ← **overflow = 0**

### كيف بنحسب الـ overflow

```verilog
wire add_overflow = (sign_a == sign_b)  && (sign_sum != sign_a);
wire sub_overflow = (sign_a != sign_b)  && (sign_sum != sign_a);
```

**المنطق للجمع:** إذا الرقمين **نفس الإشارة** (موجب+موجب أو سالب+سالب)،
النتيجة **لازم** تكون بنفس الإشارة. لو طلعت مختلفة ← overflow.
وإذا الإشارتين مختلفتين، **مستحيل** يصير overflow — لأن النتيجة أكيد بين
الرقمين.

**للطرح:** العكس. `a - b` بيصير overflow لما الإشارتين **مختلفتين**
(موجب ناقص سالب = أكبر، أو سالب ناقص موجب = أصغر).

> ⚠️ **الغلطة الشائعة:** استعمال الـ carry كمؤشر overflow. المثالين فوق
> بيثبتوا إنه غلط، وفي testbench عندك حالتين بتفحصوهم بالظبط:
> `"ADD signed overflow, no carry"` و `"ADD -1+1 carry with zero result"`.

## الطرح والـ carry: معناه "ما صار استلاف"

بالطرح، الـ carry-out معناه مختلف: بيساوي **1 لما ما يصير borrow**،
يعني `a >= b` (unsigned).

هاد مش اصطلاح عشوائي — بيطلع طبيعي من `a + (~b) + 1`.

## SLT — العملية اللي بتفرّق المصمّم الشاطر

```verilog
OP_SLT: result = {{(WIDTH-1){1'b0}}, (sign_sum ^ sub_overflow)};
```

`SLT` (Set on Less Than) بترجّع 1 إذا `a < b` بالمقارنة signed.

**الطريقة الساذجة:** اطرح `a - b` وشوف بت الإشارة. سالب ← `a < b`.
**المشكلة:** لما يصير **overflow**، بت الإشارة بينقلب وبيعطي جواب **معكوس**.

**مثال:**
```
a = -128,  b = 127
a - b = -255  →  ما بتسع بـ 8 بت  →  overflow
النتيجة المخزّنة = 1  →  بت الإشارة = 0  →  "موجب"  →  a > b  ❌ غلط!
```
الجواب الصح إن `-128 < 127`.

**الحل:** `sign_sum XOR overflow`
لما يصير overflow، بنقلب القراءة. `0 XOR 1 = 1` ← `a < b` ✅

> بالـ testbench، الحالة `"SLT -128 < 127, overflow corrected"` بتفحص هاد
> بالظبط. أي تنفيذ ما بيعالج الـ overflow بيسقط هون.

## ليش defaults قبل الـ case؟

```verilog
always @(*) begin
    result   = {WIDTH{1'b0}};
    carry    = 1'b0;
    overflow = 1'b0;

    case (opcode)
        ...
```

**السبب: منع الـ latch.**

بـ `always @(*)`، لو في فرع ما بيعطي قيمة لمخرج، Verilog بيفهم: "خليه
بيحافظ على قيمته القديمة" — وهاد **بيحتاج ذاكرة**، فالمترجم بيبني **latch**
ما إنت طلبته.

الـ latch بدارة يفترض إنها combinational = كابوس بالـ timing analysis وسلوك
غير متوقع.

**الحل:** حطّ قيمة افتراضية لكل مخرج قبل الـ `case`، وحطّ `default`.
هيك كل مسار بيعطي قيمة لكل مخرج، وما في احتمال latch.

> **سؤال متوقع:** "كيف بتتجنب الـ inferred latches؟"
> **جوابك:** defaults قبل الـ case + `default` بالـ case، وكل المخرجات
> بتنكتب بكل فرع.

## ليش `localparam` مش `` `define ``؟

`` `define `` عام على كل الملفات اللي بتترجم بعده — ممكن يتصادم مع تعريف
تاني. `localparam` محدود بالموديول، فما بيسرّب برّا.

# الجزء التاني: الـ FSM

**الملف:** `rtl/seq_detector.v`

## شو بتعمل

بتستقبل بت واحد كل clock، وبترفع `detected` لدورة وحدة كل ما تشوف
النمط **`1011`**.

## الحالات

| الحالة | يعني |
|---|---|
| `S0` | ما تطابق إشي |
| `S1` | تطابق `1` |
| `S2` | تطابق `10` |
| `S3` | تطابق `101` |
| `S4` | تطابق `1011` ← كشف! |

**كل حالة معناها "قدّيش من النمط تطابق لحد هلأ"** — هاي الطريقة الصح
لتصميم أي sequence detector.

## الـ Overlapping — أهم قرار بالتصميم

**السؤال:** بعد ما نكشف `1011`، على وين نرجع؟

**الجواب الساذج:** نرجع `S0` ونبلّش من الصفر.
**المشكلة:** بنضيّع كشوفات.

**مثال — الدخل `1011011`:**
```
1 0 1 1 0 1 1
        ↑     كشف أول عند البت الرابع
      1 0 1 1
            ↑ كشف تاني — بس بس إذا استفدنا من الـ "11" اللي بالآخر
```

لو رجعنا `S0` بعد الكشف الأول، **الكشف التاني بيضيع**.

**القاعدة:** ارجع لـ **أطول لاحقة (suffix) مما شفته هي كمان بادئة (prefix)
للنمط**.

بعد `1011`، آخر بتين `11`. وآخر `1` بادئة صالحة للنمط ← نرجع **`S1`** مش `S0`.

```verilog
S4: next_state = din ? S1 : S2;
```

> **سؤال متوقع:** "كيف تعاملت مع الـ overlapping؟"
> **جوابك:** بعد الكشف ما برجع للحالة الابتدائية. برجع للحالة اللي بتمثّل
> أطول لاحقة من المتطابق هي كمان بادئة للنمط. عندي `S3` كمان بترجع `S2` مش
> `S0` لما ييجي 0، لأن `1010` آخرها `10` وهي تطابق جزئي صالح.

## نفس المنطق بحالة S3

```verilog
S3: next_state = din ? S4 : S2;
```

إحنا بـ `101`. إجا `0` ← صار عندنا `1010`. النمط انكسر، **بس** آخر بتين
`10` = تطابق جزئي صالح ← نرجع `S2` مش `S0`.

**هاي النقطة اللي معظم الناس بتغلط فيها.**

## أسلوب الثلاث كتل (Three-block style)

```verilog
// 1. state register — الوحيد اللي فيه clock
always @(posedge clk) begin
    if (!rst_n) state <= S0;
    else        state <= next_state;
end

// 2. next-state logic — combinational
always @(*) begin
    next_state = state;
    case (state) ... endcase
end

// 3. output logic — combinational
assign detected = (state == S4);
```

**ليش تلات كتل مش وحدة؟**

- بينبني **بنك register واحد** بالظبط، وواضح وين
- منطق الانتقالات بينقرأ لحاله، فبتقدر تقارنه بمخطط الحالات
- لو دمجتهم بكتلة clocked وحدة، بيشتغل بالمحاكاة، **بس** الناتج المركّب
  بيبطّل يطابق المخطط اللي رسمته، وتصحيح الأخطاء بيصير بقراءة الـ netlist

## Blocking (`=`) مقابل Non-blocking (`<=`)

**القاعدة العملية:**

| بتستعمل | وين |
|---|---|
| `<=` (non-blocking) | جوّا `always @(posedge clk)` — يعني flip-flops |
| `=` (blocking) | جوّا `always @(*)` — يعني منطق combinational |

**ليش؟** الـ `<=` بتخلّي كل الـ registers تقرأ **القيم القديمة** وتتحدّث مع
بعض بنفس اللحظة — وهاد بالظبط شغل الـ flip-flop الحقيقي.

لو استعملت `=` جوّا كتلة clocked، النتيجة بتعتمد على **ترتيب الأسطر** —
وهاد أشهر سبب لـ **simulation-synthesis mismatch** (المحاكاة بتشتغل
والهاردوير لأ).

> **سؤال متوقع:** "إيمتى بتستعمل blocking وإيمتى non-blocking؟"
> **الجواب فوق حرفياً.** هاد سؤال شبه مضمون بأي مقابلة RTL.

## Moore مقابل Mealy

| | Moore | Mealy |
|---|---|---|
| المخرج بيعتمد على | **الحالة بس** | الحالة **+ المدخل** |
| التوقيت | متأخر دورة | أسرع دورة |
| الـ glitches | **محمي** | ممكن يمرّر glitch من المدخل |

اخترنا **Moore**:
```verilog
assign detected = (state == S4);   // ما فيها din
```

**السبب:** المخرج بينتج من register، فبيكون نظيف ومتزامن مع الـ clock.
بـ Mealy، المخرج بيتبع `din` مباشرة — فأي glitch على `din` بيمرق للمخرج.

## Synchronous مقابل Asynchronous reset

استعملنا **synchronous**:
```verilog
always @(posedge clk) begin
    if (!rst_n) state <= S0;
```

الـ `rst_n` مش بقائمة الحساسية — يعني بينقرأ **عند حافة الـ clock** زي أي
مدخل تاني.

**الميزة:** بيدخل ضمن نطاق الـ clock المحلَّل زمنياً، فالـ static timing
analysis بتشوفه. وبمعظم الـ FPGA بينحط بمدخل الـ reset تبع الـ flip-flop
نفسه بلا منطق زيادة.

**البديل** (asynchronous) بيكون `always @(posedge clk or negedge rst_n)` —
بيشتغل فوراً بلا انتظار clock، بس بيحتاج انتباه لـ **reset recovery/removal
timing**.

## ليش `rst_n` مش `rst`؟

الـ `_n` معناها **active low** — الـ reset بينشّط لما تكون القيمة `0`.
اصطلاح شائع بالصناعة، وسببه تاريخي متعلق بخصائص الدارات.

# الجزء الثالث: الـ Testbenches

## المبدأ: self-checking

```verilog
if (result !== exp_result || carry !== exp_carry || ...) begin
    errors = errors + 1;
    $display("FAIL %0s", label);
end
```

الـ testbench **بيقارن مع قيم متوقعة محسوبة بشكل مستقل**، مش بيطبع قيم
وإنت تشوفها بالـ waveform.

> **ليش هاد مهم:** اختبار بيحتاج إنسان يبصّ على waveform عشان يقرر نجح ولا
> لأ **مش اختبار انحداري (regression test)**. ما بتقدر تشغّله آلياً، وما
> بتقدر تثق فيه لما يكبر التصميم.

وبالآخر:
```verilog
if (errors != 0) $fatal(1, "ALU testbench failed");
```
يعني بيرجّع كود خروج غير صفر ← بيقدر يفشّل CI pipeline.

## ليش `!==` مش `!=`؟

`!==` بتقارن **مع حالات X و Z** كمان.
`!=` بترجّع `X` لو أي طرف فيه `X` — فالمقارنة بتفشل بصمت.

بالـ testbench لازم تمسك `X` (قيمة غير محددة) — وهي عرض شائع لوجود latch
أو إشارة غير مقادة.

## `#1` بعد تغيير المدخلات

```verilog
a = ta; b = tb; opcode = top;
#1;    // خليها تستقر
```

المنطق combinational — بس المحاكي بيحتاج **خطوة زمنية** عشان ينشر التغيير.
بلا `#1`، بتقرأ المخرج القديم.

# الجزء الرابع: VHDL مقابل Verilog

نفس الـ ALU مكتوبة بالاثنين (`vhdl/alu.vhd`). الفروقات المهمة:

## ١. الأنواع

**Verilog:** `wire [7:0]` — مجرد 8 بت. المترجم بيقرر signed ولا unsigned من
السياق.

**VHDL:** لازم تحدد:
```vhdl
signal sum : unsigned(WIDTH downto 0);
sum <= ('0' & unsigned(a)) + add_b + carry_in;
```
`std_logic_vector` **ما إله معنى رقمي إطلاقاً**. لازم تحوّله لـ `unsigned`
أو `signed` صراحةً.

**النتيجة:** VHDL أكتر إسهاباً، بس **ما بيمرّر أخطاء التحويل بصمت**.

## ٢. قائمة الحساسية

**Verilog:** `always @(*)` — تلقائي.
**VHDL:** `process(all)` — نفس الإشي (VHDL-2008).

قبل 2008 كان لازم تكتبها يدوي — ونسيان إشارة = المحاكاة بتختلف عن الهاردوير.

## ٣. ممنوع تقرأ `out` port

بـ VHDL-93، ما بتقدر تقرأ مخرج. عشان هيك في `result_i` داخلي:
```vhdl
signal result_i : std_logic_vector(WIDTH-1 downto 0);
...
result   <= result_i;
zero     <= '1' when result_i = (result_i'range => '0') else '0';
```
